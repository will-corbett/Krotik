# Krotik — Russian grammar instant-drill site

Static, no-login drill app (Svelte 5 + Vite + TypeScript strict). No backend, no analytics.
UI settings go in localStorage (`krotik.settings.v1`). Progress is **opt-in only** (`settings.progress`, off by default):
then `src/lib/progress.ts` keeps per-topic round counts, first-attempt results, the last five rounds and the date last
practised under `krotik.progress.v1`, and `src/lib/words.ts` keeps "My words" under `krotik.words.v1`: per word only its
key (`n:<id>`, `v:<id>`, `a:<id>`, `o:<word>`), band, Leitner box and the dates added and next due. Both stay in this
browser, are never sent anywhere, and are deleted when progress is turned off. Export/import (`src/lib/backup.ts`: both records
in one file, merged on import; old words-only files still import) is a file on the user's own device only. Never store answers, typed text, times or anything else, and keep the About page's description of what is
kept exact.

## Commands (Node ≥ 22.12; `.nvmrc` = 22)
On this Mac, Node 22 is keg-only: `export PATH=/opt/homebrew/opt/node@22/bin:$PATH` first.

- `npm run data` first on a fresh clone (no data is committed), then `npm run dev` / `npm run build` / `npm run preview`
- `npm test` — Vitest unit tests (tests/unit)
- `npm run e2e` — Playwright smoke tests, desktop + mobile (tests/e2e). First time: `npx playwright install chromium`
- `npm run check` — svelte-check + tsc for scripts
- `npm run data` — fetch raw sources (into gitignored data-raw/) and rebuild public/data + reports/validation.md
- `npm run data:build` — rebuild only (raw files already present)
- `npm run data:verify-overrides` — check every hand fix in overrides/overrides.yaml against Wiktionary (kaikki.org)

## Data rules (non-negotiable)
- Never ship Russian forms made up or generated by rule. Every form comes from a source
  (OpenRussian export, Wiktionary via kaikki) or is checked against one. Rule-based generation may only
  flag disagreements in the report.
- Our own Russian (Learn pages, notes, questions, the Vocabulary section's dialogues) is word-checked: every word must be a
  real form in the data. **Dialogues** (`content/words/<theme>.yaml`) are also published only once a native speaker has
  reviewed them (`reviewed: "<who>, YYYY-MM-DD"`); until then the build leaves them out of public/data and lists them in
  `reports/dialogues-for-review.md` for the reviewer. Never mark a dialogue reviewed yourself.
- Fix data in `overrides/overrides.yaml` (fix / exclude / gloss / sentence deny), never by editing shards.
  Every `fix` form must pass `npm run data:verify-overrides`.
- Generated shards in public/data are NOT committed (gitignored); `npm run data` builds them locally and CI builds
  them before tests and deploy. The build is deterministic: the same sources give byte-identical output.
- CI/deploy: `.github/workflows/deploy.yml` (GitHub Pages). Sources are cached per month, so the deployed data
  refreshes monthly; check the validation-report artifact after a refresh.
- `reports/validation.md` is regenerated each build. Read it after any pipeline change and report
  regressions honestly.
- Licences: OpenRussian/Wiktionary-derived data is CC BY-SA 4.0 (share-alike applies to our shards);
  Tatoeba sentences are CC BY 2.0 FR. Keep the About page and public/data/LICENSE.md accurate.
- Keep the site commercially usable: only sources whose licence allows commercial use (CC BY / CC BY-SA, public
  domain, MIT/OFL code and fonts); never copy third-party prose (e.g. the CEFR descriptors are Council of Europe
  copyright: we use the level names only, with our own descriptions); every page credits the data (the app's footer
  and the prerendered pages' footer). GitHub Pages' terms don't allow a site run mainly for commercial transactions,
  so a paid version would move host (change `src/shared/site.ts`).

## Layout
- `scripts/` — pipeline (TypeScript, run with tsx). `build-data.ts` orchestrates; `lib/clean-*.ts`
  clean and validate each type; `lib/sentences.ts` matches Tatoeba sentences; `lib/shard.ts` writes bands.
- `src/shared/` — code shared by app and pipeline: `normalise.ts` (answer normalisation), `forms.ts`
  (cell syntax, stress rendering), `cells.ts` (fixed cell layouts), `types.ts` (shard row formats).
- `src/lib/` — app logic, framework-free and unit-tested: `check.ts`, `queue.ts` (retry rule),
  `questions/*.ts` (one generator per mode, seeded RNG), `data.ts` (shard loading), `settings.ts`.
- Start here (`/start/`, `StartPage.svelte`): the beginner's guide (what's here, a first path of 11 topics, how drills
  work, levels). The home page shows a big "New to Krotik?" card until you've found your way (opened the
  guide, started a drill round, or pressed "Got it": `settings.guideSeen`); then it's a small link under the title. It
  never disappears, and the footer always links to it.
- Home (`Dashboard.svelte`): the Krotik header, a slim "Your last drill" strip, and five cards (Grammar, i.e. Learn & drill;
  Vocabulary; Grammar test; Reading; Your progress) — no topic list. The full topic map is the Learn page (`LearnIndex.svelte`: every topic
  with its level and Learn/Drill links, Review drills included); progress details are `/progress/`
  (`ProgressPage.svelte`, not in the menu, noindex).
- `src/components/` — Svelte UI. Pages with real addresses under `SITE_BASE` (`src/shared/site.ts`, `/Krotik/`;
  `src/lib/router.ts`): Dashboard (`/`), Grammar test (`/test/`), Learn (`/learn/`, `/learn/<topic>/`), Drill (`/drill/`
  to choose, `/drill/<topic>/` for that drill's settings), Vocabulary (`/vocabulary/`), Reading (`/reading/`), Culture
  (`/culture/`), plus `/about/`. Every Drill link
  elsewhere goes straight to `/drill/<topic>/`. Links inside the site change page without reloading (App's
  `onLinkClick` + `navigate()`, keeping `?seed`); old `#/…` addresses are rewritten to the path. Dev server:
  http://localhost:5173/Krotik/.
- Prerendering (`scripts/prerender.ts`, run by `npm run build` after `vite build`): every page gets its own
  `index.html` with its title (`src/lib/pageMeta.ts`, also used for `document.title`), description, canonical address
  and its text as plain HTML (Learn pages with their quoted sentences and IPA; form tables and quick checks are drawn by
  the app), plus `sitemap.xml` and `404.html`. Drill pages are `noindex`. The app replaces the prerendered copy when it
  starts. A project site can't have its own robots.txt (it lives at the domain root), so submit the sitemap in Google
  Search Console. Changing host or domain = changing `src/shared/site.ts`.
- Culture page (`/culture/`, `/culture/<note>/`): links in `content/culture/links.yaml`, notes in
  `content/culture/notes/<id>.md` listed in `content/culture/notes.yaml`. YAML is imported at build time by a small
  plugin in `vite.config.ts` (no runtime dependency). Note text is word-checked like Learn pages.
- Level test (`/test/`): 60 multiple-choice questions, 12 per level A1–C1, easiest first. The data build makes the
  questions (`src/lib/levelTestPool.ts` → `public/data/level-test.json`, ~30 checked candidates per question type, listed
  in the report); the app (`src/lib/levelTest.ts`) only loads that one file and draws from it, so the test starts at once.
  Every question is a real Tatoeba sentence with one gap, a plain instruction (`ASK`, no grammar terms) and the English
  translation as the cue — never a word on its own. Sources: a word's own example sentences (sentence shards) with
  other real forms of that word as wrong options; the gapped sentence drills (word in brackets); the multiple-choice
  sentence drills. Wrong options must never also fit: forms with the same spelling, cases the preposition/нет could
  also take, other past genders (я/ты could be either), long forms against short forms, sentence-final adjectives.
  Each level draws 12 of a larger pool (at most 2 per topic), ordered by a 1–3 weight, then by word frequency rank.
  B2/C1 test advanced grammar (participles, verbal adverbs, aspect, verbs of position, government), never just
  familiar grammar on rare words. Four options at A1–A2, five at B1+ (the wrong forms closest to the answer). You reach
  level L with ≥10/12 at L, ≥10/12 pooled over A1..L, and no level below L under 8/12 (`scoreTest`); slips below
  the result are pointed out. Leave out topics where two options can both be right
  (indefinite pronouns, же/ведь, colloquial particles, aspect after трудно-type words). Superlatives are left out: no
  sentence ties to one word. Each option carries a form code (`levelTestPool.ts`) so the results explain every wrong
  answer (`levelTestExplain.ts`); a spelling that is several forms is labelled as all of them. Next/Back/Submit; the
  test and its result are kept in memory (`session`) for the tab, never in storage.
- `src/lib/topics.ts` — the one list of topics and groups (Dashboard, Learn index and Drill setup all use it). A few
  topics are Learn pages only (`drill: false`: word order, complex sentences, modals, reported speech, sounds), left
  out of the Drill page and with no Drill links; their quick checks use a related drill. Each
  topic has a `level` [first met, core by] (our CEFR-style judgement, a guide not a gate) and `related` topics; Learn
  pages show both, with previous/next links in this order.
- The main menu is a bar on the logo's line at 1000px and wider, and a Menu dropdown below that (a bar there wraps
  below the logo, out of line with it). The level test is called the **Grammar test**
  everywhere: it measures grammar, not a full CEFR level, and says so.
- `content/learn/<topic>.md` — Learn pages (topic id = drill mode). Plain Markdown plus data blocks:
  `::table noun книга` (also verb, adjective, pronouns, participles <verb>, numeral <word>, possessive <word>),
  `::sentence verb читать past_f` (or `::sentence participle читать читая`), `::drill nounCases {"cases":["acc"]} 5`,
  `::examples chtoby past 3` (shortest real sentences of one sentence-drill kind), `::tatoeba 467752:книга 2171689` (real
  Tatoeba sentences by id, ":word" highlights it), `::ipa молоко хлеб` (each word's IPA from Wiktionary). The data build
  collects both into `public/data/learn.json` and fails if a sentence isn't in the corpus or a word has no standard IPA.
  Tables and sentences always come from the data. Major lessons end with **Common mistakes** (Not this | But
  this | Why, saying whether it is wrong, regional/unnatural, or correct with another meaning); a wrong example is
  always real forms used wrongly (wrong case, aspect, preposition), never a misspelt or invented form. `tests/unit/learn.test.ts` fails if any Russian word in the
  text isn't a real form in the data, or a block doesn't resolve (word in the top 1,000; sentence exists).
  Words not in the drill data go in `content/learn/words.yaml`; the data build checks them against Wiktionary.

- Learning paths (`/paths/`, `PathsPage.svelte`, `src/lib/paths.ts` logic, `src/lib/pathsData.ts` data,
  `content/paths.yaml`): for each level A1 to C1, a recommended order of steps (learn a topic, a vocabulary theme, a
  reading text, a review drill, the test), most with a line on why. A guide, not a gate. You can follow one
  (`settings.pathLevel`); with progress on, steps are ticked when the topic was drilled or half the theme's words are in
  your words (reading isn't recorded, so never ticked). `tests/unit/paths.test.ts` checks every step exists, isn't from
  a later level, and that every Vocabulary theme is on its level's path. Linked from Start here and the Learn page.
- Home page with progress on: a "Your next steps" card (weak topics, or topics due; words due; the next step on your
  path, or an invitation to choose one). With progress off it isn't shown.
- Learn page filters (level, group, and with progress on: not practised, practised, needs revision); page state only.
- Layout: the frame is 1000px wide (lists, tables, Vocabulary, Culture, Paths); drills, the test, progress and pages of
  running text (Reading texts, Start here, About, culture notes) keep 760px (`main.narrow` in App), and Learn paragraphs
  46rem.
- Report a problem (`src/lib/report.ts`, `ReportLink.svelte`, `ISSUES_URL` in `src/shared/site.ts`): a link to a new
  GitHub issue prefilled with the page and the item (drill question and expected answer, Tatoeba sentence, Reading
  text, Vocabulary theme, Learn page, test question; the footer for any page). It only opens the form: nothing is sent
  unless the reader submits it, and nothing about the reader (settings, progress, answers) goes in.

## Conventions
- Cell string syntax: variants separated by `,`; `(x)` = optional/archaic variant (accepted, not shown);
  stress = apostrophe after the vowel (`сказа'л`); ё is implicitly stressed.
- Normalisation for answers: NFC → lowercase → strip `'`/U+0301 etc. → ё→е → trim/collapse spaces.
  Pipeline and app must use the same `normalise()`.
- Adjective m/pl accusative is stored as two cells (inanimate, animate) resolved at build time by matching
  the source variants against nom/gen. Source order is unreliable; never use position.
- Shards: `{type}.b{0..3}.json` = frequency ranks 1–250, 251–1000, 1001–2500, rest. "Top N" loads
  b0..bk. Sentence shards load lazily after a round starts.
- Retry rule: wrong → comes back RETRY_GAP (10) cards later, or at the end if fewer are left (so retries work in
  unlimited rounds too); round ends only when all are answered correctly (or End round).
  Score = first-attempt correct / attempted.
- Example sentences: only shown when the highlighted word is exactly the answer form (`chooseSentence`); never
  fall back to another form of the word.
- Modes are grouped (Verbs / Adjectives / Pronouns / Nouns & numbers / Sentences / Pronunciation); each mode has a generator in
  `src/lib/questions/` and a case in `src/lib/start.ts`. Every grammar term goes through `src/lib/terms.ts`
  so it is shown with its Russian equivalent.
- Wiktionary (kaikki.org gzipped JSONL) is streamed once by `scripts/lib/wiktionary.ts`; the needed entries are cached
  in `data-raw/kaikki-extract.json`, keyed to the dump's sha256. `scripts/lib/phase-b.ts` builds participles, verbal
  adverbs, numerals and diminutives, and fills noun gender (only where both sources agree on animacy) and missing
  comparatives. Rule-based patterns there only flag disagreements in the report.
- Sentence drills (`scripts/lib/cloze.ts` → `public/data/cloze.<topic>.json`): the answer is always the word in the
  Tatoeba sentence; typed blanks must map to exactly one lemma; multiple-choice distractors must occur elsewhere
  in the corpus. Deny bad sentences by Tatoeba id in `overrides.yaml` `sentences.deny`.
- `curated/*.yaml` are small hand-made grammar lists (verb government, motion prefixes, position verbs, time
  words). They state grammar facts only — never forms — and every entry is checked against the data; misses
  are listed in the report. Edit them freely, then run `npm run data:build`.
- `scripts/lib/phase-f.ts` (batch 4): adverbs paired with their adjective by the Wiktionary etymology (or the
  short neuter form), second prepositional / partitive forms of masculine nouns (only -у/-ю forms that differ
  from the ordinary ones), and dates data (month genitives, век). Bad adverb pairings go in `overrides.yaml`
  `adverbs.exclude`. The Wiktionary extract has a version number (`EXTRACT_VERSION`): bump it when its shape changes.
- Agreement questions (adjectives, possessives, ordinals, participles, самый, какой/чей) pair a word only with nouns it
  is really used with: `scripts/lib/collocations.ts` collects adjacent, agreeing adjective/participle + noun pairs from
  Tatoeba into `collocations.json`; `src/lib/pairs.ts` picks from them (наш/ваш borrow мой/твой). A word with no real
  partner among the loaded nouns is simply not asked. Never pair words at random.
- `overrides.yaml` `nouns.counting` holds counting forms (пять челове'к, пять ле'т), verified like fixes.
- `?seed=N` in the URL makes question generation reproducible (used by e2e tests).
- Themes: `krotik` (default; logo colours — cream #FDF2E7, charcoal #090C13, orange #E36B1C), system, light,
  dark. The orange is only 3:1 on cream, so it fills buttons/bars (`--primary-bg`, charcoal text) and small orange
  text uses `--accent` #9A420B. Logo files are in `public/brand/`.
- Accessibility: keyboard-only flow (Enter submits and continues), aria-live feedback, visible focus,
  contrast checked by axe in both themes, reduced motion respected, no horizontal scroll at phone width.
- Culture links: only a creator's or rights holder's own channel or site (no re-uploads, no unclear rights);
  no music or lyrics; no sanctioned outlets or people; nothing whose main theme is politics or the war; links only,
  never embeds (no third-party requests or cookies); descriptions in our own words; nothing that would stop the site
  being run commercially. Check each link by hand before adding it and set `checked`. `npm run links:check` runs
  monthly (`.github/workflows/links.yml`); 401/403/429 from bot protection and repeated timeouts are reported, not
  failed. Each link has a type, level range, region (russia, kazakhstan, central-asia, ukraine, caucasus, baltics,
  worldwide) and topic; the page filters on these plus free text, and shows 20 links a page (type order; a filter starts again at page 1). Check what a channel actually posts (recent videos),
  not just its name: a channel called "Simple Russian" turned out to be political.
- Vocabulary (`vocab`, group "Words", `learn: false`): `scripts/lib/vocab.ts` builds `words.b{0..3}.json`
  (`[key, accented, meaning, type, aspect|gender]`) from every noun, verb and adjective plus OpenRussian's others.csv,
  banded per type like the drill shards; other words are ranked by their FrequencyWords count (credited on the About
  page), since the source's order puts some (тут, уж) last. Left out: names, empty/grammar-note/non-English meanings,
  pronoun case forms, and nouns/adjectives spelt like a verb or other word (тут "mulberry") unless `overrides.yaml`
  `vocab.keep` lists them; `vocab.gloss` gives a clearer meaning, `vocab.exclude` drops a word. Recognise = choose the
  English meaning of four (wrong ones of the same type, sharing no English word with the right one; `Question.meaning`);
  Recall = type the word, where same-type (and same-aspect) words sharing a meaning item are accepted and named, and the
  aspect partner is named as a near miss. With progress on, every word answered is scheduled (right first time → next box,
  1/3/7/14/30/60 days; wrong → box 0, due tomorrow); "My words that are due" reviews them, most overdue first. The
  Progress page lists them (Remove, Export, Import, Delete). Reading: every explained word carries its key and band;
  each text lists up to 15 key words (band 2+, not among FrequencyWords' 3,000 commonest forms, which overrules a few
  misplaced source ranks), with Practise these and Add all; a clicked/tapped/focused word's box is pinned and offers
  Add to my words.
- Vocabulary section (`/vocabulary/`, `/vocabulary/<theme>/`; content in `content/words/`; `WordsIndex.svelte`, `WordsTheme.svelte`; `scripts/lib/themes.ts`):
  47 themes (9–10 at each of A1, A2, B1, B2, C1; C1 is half about the language itself: formal style, shades of
  meaning, word families; buttons at the top of the index jump to a level) listed in
  `content/words/themes.yaml`, each `content/words/<id>.yaml` with title (en/ru), level, blurb,
  word groups, optional `use` (word → Tatoeba id, where the shortest sentence is an idiom or off-theme) and dialogues.
  Words are named by dictionary form (`есть:v` for a spelling that is several words, `не'бо` by stress, `"соль =
  salt"` for our own meaning); the build fails unless each is exactly one word in the lists. Each word gets the
  shortest real Tatoeba sentence using it (never a crude or violent one), opened under its row by the arrow beside
  the word. Dialogues use the Reading machinery
  (`ExplainedText.svelte`: every word tappable; English on request); names in them must be declared in `names`.
  Output: `themes.json` + `theme.<id>.json`, prerendered and in the sitemap. Theme pages practise their words both
  ways round (App's `practise(keys, direction)`) and add them to My words. The word lists also take every source noun,
  verb and adjective the drills leave out for missing or unclear forms (кофе, деньги, ветер, свет): words to learn,
  by headword and meaning only.
- Review drills (group "Review", `learn: false` in topics.ts, no Learn page): **Mixed review** (`mixed`) interleaves
  questions from chosen topics, each with that topic's own settings; **Translate and compare** (`translate`) shows a
  Tatoeba English sentence, you type Russian, then compare with the Tatoeba Russian and mark yourself (`selfMark`;
  only an exact match is marked right automatically). The end screen breaks results down by question type (the first
  term of the task line) or, in mixed rounds, by topic (`src/lib/breakdown.ts`).
- Culture: each resource type has a suggested activity (`TYPE_ACTIVITY` in `src/lib/culture.ts`), shown under its
  heading; our own suggestions, in English.
- Robustness (`tests/e2e/robust.spec.ts`): a failed data request shows a plain message (`getJson` in data.ts) and
  isn't cached, so trying again works; Learn blocks say when their data didn't load; sentences are optional in drills.
  Reloading mid-drill returns to that drill's settings (rounds aren't stored). Back/Forward to a Drill address always
  shows that page (choose or settings), leaving any round in progress.
- Politics in reading texts (owner's decision, 2026-11-08): historical political material about events before 2014
  may be included (it needn't be); nothing about politics since then, nothing about the war, and no sanctioned outlets
  or people. Culture links keep their stricter rule (nothing whose main theme is politics or the war).
- Reading (`/reading/`, `/reading/<id>/`; `ReadingIndex.svelte`, `ReadingText.svelte`): whole stories and scenes of
  public-domain literature listed in `curated/literature.yaml` (Tolstoy's Second Russian reader; Chekhov's Медведь and
  Предложение), fetched from Russian Wikisource at pinned revisions and never changed. `scripts/lib/literature.ts`
  explains every word: our data (dictionary form, meaning, which form), else Wiktionary; flags: old-fashioned
  (Wiktionary has it only as archaic/obsolete/dated; mis-tags go in `notOld` with a reason), the polite -с, names,
  and hyphenated speech (-то, repeats, stammers, spelt out). Words neither source has get an English meaning by hand in
  `glosses` (marked "our explanation"). A text is published only with every word explained and questions in
  `content/reading/questions.yaml` (EN + RU, same options; the Russian is word-checked like Learn pages; our own words
  about the story, never about wording). Output: `reading.json` + `reading.<id>.json`; prerendered with full text.
  Hover/tap/focus shows a word; arrow keys move between words (one Tab stop). Questions are in Russian by default (`settings.questionLang`; English on request).
- Russian beyond Russia: a hub note plus one note per country or region (`notes.yaml` entries with `parent`, listed on
  the hub, not the Culture page; `region` lists that region's Culture links). Each gives the status of Russian, census
  figures with year and a linked source, accent, and local words (sourced from Wiktionary or our data; new words go in
  `content/learn/words.yaml`, so the build verifies them). Language only: no political commentary. Notes support links
  `[text](https://…)` and `[text](note:id | learn:id | reading:id)`.
- Drill task lines are chips (`TermText variant="chips"`): English and Russian term on one line; a pronoun already in
  the frame isn't repeated.
- Every typed answer offers the on-screen Cyrillic keyboard (drills and Learn quick checks share `settings.keyboard`);
  the Culture search box is the only exception.
- Drills whose verb can be in several tenses let you choose them (sentence drills carry the tense in the row kind
  after "@": `impf@past`).
- Within each group in `topics.ts`, topics run from the most basic and most needed to the more advanced or less
  essential; "Getting started" (the alphabet) comes first.
- Deploys: GitHub Pages sometimes leaves a deployment stuck ("deployment_queued" / "syncing_files"); a fresh one
  usually gets through. The deploy job gives up on an attempt after 3 minutes and tries again with 5, then 10 minutes
  (a deployment can only be named after a real commit, so retries reuse the same one); run the workflow by hand with
  `test_retry` to check the retry path. If all three stall, push an empty commit. Browser tests run on 4 workers in CI.
- Small, well-named commits. Say why before adding a dependency.
